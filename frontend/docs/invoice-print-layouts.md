# قالب‌های چاپ فاکتور

سه اندازه موجود است: `a4-landscape` (قالب MRT قبلی)، `a4-portrait` و `a5-portrait`.

- PDF: `GET /api/invoices/{id}/pdf?format=a5-portrait`؛ مجوز `Invoice.Read`، پاسخ Blob PDF، بدون cache.
- دریافت تنظیمات: `GET /api/invoice-print-layouts/{format}`؛ مجوز `CompanySettings.Read`.
- ذخیره: `PUT /api/invoice-print-layouts/{format}`؛ مجوز `CompanySettings.Update`؛ بدنه `{layout, version}`. پاسخ `{layout, version}` و کنترل نسخه برای جلوگیری از بازنویسی ویرایش هم‌زمان.
- پیش‌نمایش بدون ذخیره: `POST /api/invoice-print-layouts/preview/{invoiceId}`؛ بدنه layout، مجوزهای `CompanySettings.Update` و `Invoice.Read`. کنترل دسترسی شعبه و مشخصات لازم چاپ مانند PDF عادی اعمال می‌شود.

`layout` شامل `format`, `title` (حداکثر ۱۰۰ کاراکتر)، `fontSize` (۷ تا ۱۲)، `margin` (۰٫۵ تا ۱٫۵ سانتی‌متر)، `headerColor` (رنگ hex)، `showCode`, `showDiscount`, `showSignatures` است. عنوان به‌صورت دادهٔ متنی ثبت می‌شود؛ عبارت قابل اجرا یا MRT آپلود نمی‌شود.

ویرایشگر: `/invoice-print-layouts`، قابل دسترسی از فهرست و منوی چاپ. نمای داخل صفحه شماتیک است؛ PDF پیش‌نمایش، صفحه‌بندی واقعی را نشان می‌دهد. ویرایشگر فعلی تنظیمات عنوان، رنگ، فونت، حاشیه و ستون‌های مشخص را تغییر می‌دهد؛ برای جابه‌جایی آزاد اجزای MRT از Designer مستقل استفاده می‌شود.

تنظیمات برای همه کاربران مشترک‌اند و برای هر اندازه جدا در `App_Data/InvoiceLayouts` کنار برنامهٔ بک‌اند ذخیره می‌شوند. در انتشار، `InvoicePrinting:LayoutDirectory` را به پوشهٔ پایدار دارای دسترسی نوشتن حساب سرویس تنظیم و از آن پشتیبان تهیه کنید. فایل‌ها باید خارج از مسیر عمومی وب باشند. پیاده‌سازی کنترل هم‌زمانی برای یک فرایند سرور است؛ در استقرار چندنمونه‌ای، ذخیره‌ساز باید مشترک و قفل توزیع‌شده/دیتابیس داشته باشد.

برای فعال‌شدن مسیرهای جدید، بک‌اند باید Build و مجدداً اجرا شود؛ migration دیتابیس اضافه نشده است. قالب MRT افقی اصلی تا پیش از ذخیره تنظیمات سفارشی همان فایل قبلی باقی می‌ماند. مبلغ‌ها، کسور، واحد تاریخی و دسترسی شعبه از فاکتور ذخیره‌شده خوانده می‌شوند.
