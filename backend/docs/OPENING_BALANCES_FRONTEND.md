# راهنمای فرانت‌اند: ثبت اطلاعات اول دوره

این قابلیت در بک‌اند پیاده‌سازی شده است. تغییرات رابط کاربری توسط فرانت‌اند انجام شود. تمام مبالغ ریال‌اند. ورود تاریخچه قبلی لازم نیست؛ مانده و تعداد موجود هنگام شروع کافی است.

## صفحه پیشنهادی

صفحه «اطلاعات اول دوره» با دو تب «طرف حساب‌ها» و «موجودی کالاها» بسازید. در فرم طرف حساب و کالا نیز لینک ورود به همین صفحه با فیلتر همان رکورد قرار دهید. تاریخ شروع را با تقویم فارسی دریافت و تاریخ واقعی میلادی UTC ارسال کنید؛ تبدیل تاریخ نباید روز انتخاب‌شده را جابه‌جا کند. روز مالی شروع را به صورت تاریخ UTC ساعت 00:00:00Z ارسال کنید و در نمایش دوباره همان روز را حفظ کنید. این قابلیت سال مالی/سند افتتاحیه دفتر کل نیست و شروع مجدد سالانه را مدیریت نمی‌کند.

تاریخ پیش‌فرض مشترک در صفحه باشد، ولی API تاریخ را برای هر رکورد ذخیره می‌کند. شناسه شعبه از طرف حساب یا انبار گرفته می‌شود؛ branchId در بدنه ارسال نکنید. کاربران معمولی فقط شعبه خود و مدیر/ستاد طبق دسترسی فعلی شعب را می‌بینند.

## APIها

مبدأ نمونه: https://localhost:7000. تمام درخواست‌ها Authorization: Bearer TOKEN دارند.

| روش | مسیر | نتیجه |
|---|---|---|
| GET | /api/opening-balances/contacts?contactId=2 | آرایه مانده‌ها؛ فیلتر اختیاری |
| POST | /api/opening-balances/contacts | ایجاد؛ پاسخ 200 و رکورد |
| PUT | /api/opening-balances/contacts/{id} | ویرایش؛ پاسخ 200 و رکورد |
| DELETE | /api/opening-balances/contacts/{id}?rowVersionBase64=... | حذف منطقی؛ پاسخ 204 |
| GET | /api/opening-balances/inventory?warehouseId=1&itemId=1 | آرایه موجودی‌ها؛ هر دو فیلتر اختیاری |
| POST | /api/opening-balances/inventory | ایجاد؛ پاسخ 200 و رکورد |
| PUT | /api/opening-balances/inventory/{id} | ویرایش/تکمیل بها؛ پاسخ 200 و رکورد |
| DELETE | /api/opening-balances/inventory/{id}?rowVersionBase64=... | حذف منطقی و برگشت اثر موجودی؛ پاسخ 204 |

لیست‌ها صفحه‌بندی ندارند و رکوردهای فعال مجاز را برمی‌گردانند. نبود رکورد، آرایه خالی است. GET تکی وجود ندارد؛ از فیلتر یا آرایه استفاده کنید. PUT بدنه کامل می‌خواهد؛ PATCH وجود ندارد.

## ثبت طرف حساب

```json
{
  "contactId": 2,
  "dateUtc": "2026-10-17T00:00:00Z",
  "amount": "50000000.00",
  "isDebit": true,
  "note": "مانده بر اساس اکسل هنگام شروع کار"
}
```

- isDebit=true: «طرف حساب به ما بدهکار است»؛ طلب ما و مانده مثبت.
- isDebit=false: «ما به طرف حساب بدهکاریم»؛ بدهی ما و مانده منفی.
- انتخاب جهت الزامی است؛ به طور پیش‌فرض هیچ گزینه‌ای را انتخاب نکنید.
- مبلغ همیشه مثبت و حداکثر دو رقم اعشار است؛ جهت را با علامت منفی ارسال نکنید. مانده صفر نیازمند رکورد نیست.
- برای هر طرف حساب فقط یک مانده فعال داریم. نوع مشتری/تأمین‌کننده جهت را تعیین نمی‌کند.
- پرداخت/دریافت بعدی بدون linkedInvoiceId می‌تواند مانده طرف حساب را تغییر دهد. مانده اول دوره، invoiceId نیست؛ شناسه آن را به فیلد linkedInvoiceId ندهید.

## ثبت کالا

```json
{
  "warehouseId": 1,
  "itemId": 1,
  "dateUtc": "2026-10-17T00:00:00Z",
  "quantity": "10.000",
  "unitCost": "3000.0000",
  "note": "شمارش موجودی هنگام شروع"
}
```

- quantity مثبت، حداکثر سه رقم اعشار؛ unitCost نامنفی، حداکثر چهار رقم اعشار.
- بهای واحد یعنی بهای خرید/تمام‌شده، نه قیمت فروش. هر کالا و انبار رکورد مستقل دارد.
- اگر بها معلوم نیست، unitCost=null ارسال کنید. تعداد بلافاصله در موجودی اعمال می‌شود. null را به صفر تبدیل نکنید؛ صفر یعنی بهای مشخصِ صفر.
- ارزش کل از quantity × unitCost محاسبه و با گردکردن دور از صفر به دو رقم اعشار برگردانده می‌شود.
- فیلد ورود اصلی، بهای هر واحد باشد. نمایش مبلغ کل فقط محاسباتی است. در صورت ارائه ورود «مبلغ کل»، فرانت بهای واحد را با دقت چهار رقم اعشار استخراج و مبلغ کل نهایی گرد‌شده را پیش از ذخیره نمایش دهد؛ API totalCost ورودی ندارد.
- فقط کالاهای Inventory (نوع 1 در enum فعلی ItemType) مجازند؛ خدمات، هزینه و دارایی ثابت موجودی اول دوره ندارند.
- ثبت برای کالایی که از قبل در همان انبار گردش یا موجودی فعال دارد رد می‌شود تا موجودی دو بار ثبت نشود. اضافه انبارگردانی قدیمی خودکار تبدیل نمی‌شود.

## پاسخ مشترک

```json
{
  "id": 1,
  "branchId": 1,
  "dateUtc": "2026-10-17T00:00:00Z",
  "contactId": null,
  "warehouseId": 1,
  "itemId": 1,
  "amount": null,
  "isDebit": null,
  "quantity": 10,
  "unitCost": 3000,
  "totalCost": 30000,
  "valuationPending": false,
  "note": "شمارش موجودی هنگام شروع",
  "rowVersionBase64": "AAAAAAAACNk="
}
```

برای طرف حساب، contactId/amount/isDebit مقدار دارند و فیلدهای کالایی null هستند. valuationPending فقط در کالای بدون بها true است؛ totalCost هم null خواهد بود. مقادیر عددی پاسخ JSON number هستند؛ ورودی decimal هم رشته و هم عدد می‌پذیرد. برای مبالغ بزرگ از کتابخانه اعشاری و پارسر حفظ‌کننده دقت استفاده کنید؛ قرارداد فعلی JSON number تضمین دقت Number جاوااسکریپت برای مقادیر بزرگ ندارد. ورودی ارقام فارسی/عربی را به ASCII تبدیل کنید و جداکننده هزارگان نفرستید.

نام‌ها در پاسخ نیستند؛ با لیست فعلی کالا/انبار/طرف حساب نگاشت کنید. برای جدول‌ها، نام کالا، نام انبار یا طرف حساب، تاریخ، تعداد/جهت، بها/مبلغ، وضعیت ارزش‌گذاری و عملیات را نمایش دهید.

## ویرایش، حذف و محدودیت‌ها

در PUT، rowVersionBase64 پاسخ آخر را همراه تمام فیلدهای بدنه اصلی ارسال کنید. در DELETE با HttpParams ارسال کنید تا + و / و = در Base64 درست URL-encode شوند. پس از ذخیره، نسخه جدید پاسخ را جایگزین کنید؛ روی 409 لیست را بازخوانی و از کاربر بخواهید تغییرات را دوباره بررسی کند.

طرف حساب رکورد یا کالا/انبار رکورد قابل تغییر نیست؛ قبل از شروع گردش می‌توان حذف و مجدداً ایجاد کرد. برای طرف حساب پس از ثبت هر فاکتور/پرداخت/چک فعال، ویرایش و حذف مسدود می‌شود. تاریخ اول دوره نمی‌تواند بعد از تاریخ گردش قبلی فاکتور یا پرداخت باشد.

برای کالا، بعد از هر گردش دیگر در همان کالا/انبار، تعداد، تاریخ و حذف قفل است. تکمیل/تصحیح unitCost و توضیح با ثابت نگه داشتن تعداد و تاریخ مجاز است. این کار تعداد فعلی را تغییر نمی‌دهد. API در حال حاضر پرچم canEdit/canDelete ندارد؛ خطای سرور مرجع نهایی است.

تاریخ باید معتبر و حداکثر زمان فعلی باشد. توضیح حداکثر 500 نویسه است. حذف‌ها منطقی و همراه ثبت سابقه تغییرات هستند. ثبت اول دوره، فروش/خرید/مالیات جدید نمی‌سازد و هیچ فاکتور ساختگی تولید نمی‌کند.

## موجودی و گزارش‌ها

نوع جدید StockMovementType.OpeningBalance = 9 را با عنوان «موجودی اول دوره» در نمایش و فیلتر گردش انبار اضافه کنید. از فرم عمومی گردش انبار آن را ارسال نکنید؛ ثبت آن فقط از API اول دوره مجاز است. موجودی منفی همچنان در سرویس و دیتابیس ممنوع است. پس از ثبت ده عدد، فروش بیش از موجودی باقی‌مانده رد می‌شود.

مانده طرف حساب و گردش حساب، مانده اول دوره و برگشت از فروش/خرید را لحاظ می‌کنند. داشبورد، خالص طلب/بدهی هر طرف حساب را با مانده اول دوره و پرداخت‌ها جمع می‌زند؛ در نتیجه دریافت یا پرداخت بدون لینک فاکتور نیز اثر دارد. مانده فاکتورهای قدیمی تغییر نمی‌کند. اول دوره در بازه گزارش یک ردیف مستقل است و اگر قبل از بازه باشد در مانده انتقالی لحاظ می‌شود؛ دوباره جمع نکنید.

ارزش اولیه کالا در رکورد اول دوره نگهداری می‌شود. این تغییر موتور بهای تمام‌شده FIFO/میانگین موزون یا محاسبه مجدد سود فروش‌های گذشته اضافه نمی‌کند. وضعیت تکمیل‌نشده را هشدار دهید و سود/ارزش نهایی را از این فیلد به‌تنهایی استنتاج نکنید.

## مجوزها

| عملیات | مجوزهای لازم (همه با هم) |
|---|---|
| خواندن طرف حساب | Contact.Read |
| ثبت/ویرایش/حذف طرف حساب | CompanySettings.Update و Contact.Update |
| خواندن کالا | Stock.Read |
| ثبت/ویرایش/حذف کالا | CompanySettings.Update و StockMovement.Create |

این محدودیت عمداً ثبت اول دوره را به کاربران مسئول تنظیمات محدود می‌کند؛ نقش مدیر Seed این مجوزها را دارد؛ برای نقش‌های دیگر مجوزهای لازم را جداگانه بررسی کنید. از مجوزهای جاری برای نمایش دکمه‌ها استفاده کنید.

## خطاها و تجربه کاربری

400: بدنه/فیلد نامعتبر؛ 401: ورود؛ 403: مجوز ناکافی؛ 404: رکورد غیرمجاز/ناموجود؛ 409: تعارض نسخه؛ 422: قواعد کسب‌وکار مانند تکرار، تاریخ نادرست یا گردش قبلی. title، detail و errors فارسی‌اند. detail را به کاربر نشان دهید. دکمه ذخیره هنگام ارسال غیرفعال و ارسال تکراری مسدود باشد؛ در پاسخ نامعلوم شبکه، قبل از تکرار POST ابتدا GET فیلترشده انجام دهید.

فایل اکسل فعلاً API آپلود/ورود گروهی ندارد. نسخه اولیه فرم ورود دستی است. اگر فرانت ورودی اکسل می‌سازد، باید سطرها را پیش‌نمایش و اعتبارسنجی کند و با API تک‌رکوردی ارسال کند؛ موفقیت/شکست هر سطر را نگه دارد، چون تراکنش گروهی وجود ندارد. شماره سطر و خطاها را نمایش دهید و سطرهای موفق را دوباره نفرستید.
