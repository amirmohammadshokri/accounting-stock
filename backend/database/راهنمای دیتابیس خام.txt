راهنمای فارسی ساخت دیتابیس خام حسابداری و انبار
=============================================

این بسته شامل ساختار کامل SQL Server و راه‌انداز داده‌های پایه فارسی است.
هیچ فاکتور، سفارش، مشتری، کالا، مانده، چک، پرداخت یا اطلاعات عملیاتی سیستم قبلی
در آن وجود ندارد. این بسته بکاپ دیتابیس کاری نیست.
داده‌های پایه با همان StartupDataSeeder سورس ساخته می‌شوند؛ منطق جداگانه و ناسازگار ندارند.

حساب اولیه
----------
ایمیل ورود: admin@demo.local
نام نمایشی: مدیر سامانه
نقش: مدیر سامانه، با تمام دسترسی‌های برنامه
رمز: هنگام راه‌اندازی مقصد خودتان تعیین می‌کنید؛ رمز مشترک داخل Git وجود ندارد.
اگر می‌خواهید همان رمز قبلی را داشته باشید، همان رمز را هنگام راه‌اندازی وارد کنید،
به شرطی که حداقل ۱۲ نویسه و شامل حرف بزرگ و کوچک انگلیسی و رقم باشد.
حساب دیگری با نام کاربر فعلی لازم نیست؛ طبق انتخاب شما کاربر فعلی همان مدیر است.

داده‌های پایه
-------------
تنظیمات اولیه شرکت با عنوان فارسی، شعبه مرکزی، انبار اصلی و واحدهای پرس، عدد،
کیلوگرم، بسته، لیتر، ساعت و ماه ساخته می‌شوند. نقش‌ها و شرح آن‌ها فارسی‌اند:
مدیر سامانه، مدیر کسب‌وکار، سرپرست حسابداری، کارشناس حسابداری، مسئول انبار و کارشناس فروش.
فقط حساب مدیر اولیه ساخته می‌شود؛ نقش‌های دیگر آماده‌اند و کاربرانشان را مدیر در
خود برنامه ایجاد می‌کند. صندوق، حساب بانکی، طرف حساب و کالا باید مطابق کسب‌وکار
واقعی وارد شوند؛ این ابزار اطلاعات مالی یا هویت تجاری ساختگی ایجاد نمی‌کند.

روش پیشنهادی روی ویندوز ۶۴ بیتی
-------------------------------
۱. SQL Server را روی سیستم مقصد یا سرور جدا نصب و آماده کنید. برای مثال SQL Server 2022.
   حساب مورد استفاده باید مجوز ایجاد دیتابیس یا اعمال ساختار در دیتابیس مقصد داشته باشد.
۲. ZIP آماده AccountingDb-Raw-fa را کامل استخراج کنید.
۳. فایل database-settings.local.json کنار Initialize-RawDatabase.cmd را با Notepad
   باز کنید و کانکشن مقصد را در ConnectionStrings.Default وارد و ذخیره کنید.
   نمونه آماده، SQL محلی با Windows Authentication و دیتابیس AccountingDb_New است:
   Server=localhost;Database=AccountingDb_New;Integrated Security=True;Encrypt=True;TrustServerCertificate=True;MultipleActiveResultSets=True
   اگر Instance شما SQLEXPRESS است، مقدار Server در متن JSON باید این‌طور باشد:
   Server=localhost\\SQLEXPRESS
   بک‌اسلش در فایل JSON دو بار نوشته می‌شود.
۴. Initialize-RawDatabase.cmd را اجرا کنید. نیازی به نصب SDK یا .NET جداگانه نیست؛
   Runtime لازم همراه ابزار آماده قرار دارد.
   کانکشن از فایل خوانده می‌شود و آدرس یا رمز SQL دوباره پرسیده نمی‌شود.
۵. رمز اولیه مدیر برنامه را هنگام درخواست وارد کنید؛ این رمز با رمز SQL متفاوت است.
۶. نام سرور و دیتابیس را بررسی و فقط در صورت درست بودن YES وارد کنید.
۷. ابزار ساختار را از migrationها ایجاد و داده‌های پایه را ثبت می‌کند.
۸. در سیستم اجرای برنامه، اتصال همین دیتابیس جدید را در appsettings.Production.json
   تنظیم و سرویس‌ها را Restart کنید؛ سپس با admin@demo.local و رمز انتخابی وارد شوید.

نام حساب SQL با حساب ورود برنامه متفاوت است: اولی برای اتصال بک‌اند به SQL است؛
دومی همان admin@demo.local برای صفحه ورود برنامه است.
برای SQL Authentication، مقدار Default را مطابق نمونه زیر تنظیم کنید:
  Server=192.168.1.50,1433;Database=AccountingDb_New;User ID=YOUR_SQL_USER;Password=YOUR_SQL_PASSWORD;Encrypt=True;TrustServerCertificate=True;MultipleActiveResultSets=True
برای Windows Authentication، User ID و Password لازم نیست و Integrated Security=True
می‌ماند؛ حساب فعلی ویندوز باید مجوز لازم روی SQL داشته باشد.
اگر در رمز کوتیشن یا بک‌اسلش دارید، قواعد escaping فایل JSON را رعایت کنید.
ابزار هیچ فایل appsettings یا آدرس SQL فعلی پروژه را تغییر نمی‌دهد.
ساخت دیتابیس جدید، برنامه نصب‌شده را خودکار به آن متصل نمی‌کند.

روش اختیاری با SSMS
-------------------
اگر فقط می‌خواهید اسکریپت SQL را اجرا کنید:
۱. در SSMS یک دیتابیس خالی ایجاد و در نوار انتخاب دیتابیس همان را انتخاب کنید.
۲. AccountingDb.Schema.sql را در همان دیتابیس اجرا کنید. ساختار و تاریخچه migrationها ایجاد می‌شود.
۳. برای ساخت داده‌های پایه و حساب مدیر، Initialize-ExistingRawSchema.cmd را اجرا کنید
   و قبل از اجرا کانکشن همان دیتابیس را در database-settings.local.json تنظیم کنید.
اسکریپت SQL به‌تنهایی رمز مدیر یا حساب اولیه ایجاد نمی‌کند؛ این کار با ابزار انجام می‌شود
تا رمز با الگوریتم خود برنامه هش شود و متن یا هش خصوصی آن داخل Git ذخیره نشود.
فایل SQL برای اجرا در SSMS یا ابزار سازگار با جداکننده GO تولید شده است.
هر دسته دستور، اجرای اشتباه روی master، model، msdb و tempdb را متوقف می‌کند.

حفاظت از داده‌های موجود
-----------------------
راه‌انداز عادی دیتابیس دارای جدول را نمی‌پذیرد؛ نام دیتابیس جدید انتخاب کنید.
حالت ExistingRawSchema برای ساختار خامی است که با اسکریپت ساخته‌اید یا برای اجرای
مجدد راه‌اندازی اولیه؛ دیتابیس دارای اطلاعات عملیاتی یا جدول ناشناخته پر، رد می‌شود.
هیچ دستور حذف یا پاک‌سازی اطلاعات عملیاتی در ابزار وجود ندارد.
در اجرای مجدد، حساب و رمز کاربر موجود بازنشانی نمی‌شود و اطلاعات لایسنس شرکت حفظ می‌شود.
پیش از اجرای migration روی دیتابیس موجود از آن بکاپ بگیرید.
ابزار می‌تواند خطای SQL را با شماره نمایش دهد؛ تنظیمات اتصال، مجوز SQL و شبکه را بررسی کنید.

ساخت مجدد ابزار و اسکریپت توسط برنامه‌نویس
----------------------------------------
فرمان‌ها را از پوشه backend در PowerShell اجرا کنید:

راه ساده برای تولید اسکریپت، ابزار مستقل و ZIP با هم:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\database\Build-RawDatabase.ps1

خروجی این فرمان در output با شماره زمان ساخته می‌شود و فایل‌های خصوصی وابستگی‌ها
را خودکار از بسته ابزار کنار می‌گذارد. برای اجرای مرحله‌ها به‌صورت جداگانه:

  dotnet run --project .\Accounting.DatabaseSetup\Accounting.DatabaseSetup.csproj -c Release -- export-schema .\database\AccountingDb.Schema.sql

  dotnet publish .\Accounting.DatabaseSetup\Accounting.DatabaseSetup.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -o .\output\AccountingDb-Raw-fa\tool

فایل‌های موجود در backend\database را کنار پوشه tool در output\AccountingDb-Raw-fa کپی کنید.
در ساخت دستی، Initialize-Database.ps1 را هم کپی و از database-settings.example.json
یک کپی با نام database-settings.local.json در بسته خروجی ایجاد کنید.
فایل‌های *.private.json یا تنظیمات خصوصی که از وابستگی‌ها به خروجی کپی شده‌اند،
برای ابزار دیتابیس لازم نیستند و باید پیش از بسته‌بندی از خروجی ابزار کنار گذاشته شوند.
پس از هر migration جدید، اسکریپت ساختار و ابزار آماده را دوباره تولید کنید.
اسکریپت ساختار شامل migration نشست ۲۴ ساعته و بی‌کاری نیز هست.

حالت خودکار برای مدیر استقرار
----------------------------
در صورت نیاز، ابزار connection و رمز اولیه را از متغیرهای محیطی زیر می‌خواند:
  ACCOUNTING_SETUP_CONNECTION
  ACCOUNTING_INITIAL_ADMIN_PASSWORD
راه‌انداز CMD اتصال را از فایل می‌خواند و فقط برای پردازش ابزار در متغیر اول قرار می‌دهد؛
سپس مقدار قبلی متغیر را برمی‌گرداند. اجرای مستقیم EXE نیز همچنان این متغیرها را پشتیبانی می‌کند.
همچنان تأیید YES لازم است. این متغیرها را در فایل قابل Push ثبت نکنید و پس از کار پاک کنید.
فرمان initialize با تنظیمات ذخیره‌شده در appsettings توسعه کاری ندارد.

چه چیزهایی را Push کنیم؟
------------------------
سورس Accounting.DatabaseSetup، تغییرات SeedData، فایل SQL ساختار و این راهنما قابل ثبت‌اند.
رمز اولیه مدیر در هیچ‌یک از آن‌ها ذخیره نشده است.
خروجی‌های backend\output، فایل‌های appsettings.Development.json و
appsettings.Production.json واقعی، کلیدهای private، گواهی‌ها و بکاپ‌های SQL را Push نکنید.
فایل appsettings.Production.example.json فقط نمونه فاقد رمز واقعی است.
database-settings.example.json نمونه عمومی است؛ فایل database-settings.local.json واقعی
ممکن است رمز SQL داشته باشد و باید خصوصی بماند. ساخت بسته از نمونه عمومی استفاده
می‌کند و کانکشن خصوصی سیستم سازنده را وارد ZIP نمی‌کند.
این فایل را روی تنظیمات مقصدِ موجود بدون ادغام و بررسی جایگزین نکنید.
gitignore جلوی افزودن معمول را می‌گیرد؛ فایل‌های خصوصی را با git add -f وارد Git نکنید.

فرانت‌اند و نشست
----------------
تغییرات مدیریت نشست در پوشه frontend قرار دارند: خروج پس از بی‌کاری، سقف ۲۴ ساعته،
تمدید کنترل‌شده و هدایت به ورود. عنوان‌ها و داده‌های پایه به فارسی هستند.
روی سیستم مقصد باید نسخه جدید بک‌اند و فرانت‌اند هر دو منتشر شده باشند؛ ZIP قدیمی
به‌صورت خودکار به‌روزرسانی نمی‌شود.
