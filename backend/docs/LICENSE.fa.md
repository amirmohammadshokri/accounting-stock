# مدیریت اعتبار نرم‌افزار برای مالک سرور

اعتبار برای کل سامانه و همه شعب است. فیلد `CompanySettings.LicenseExpiresAtUtc` از نوع `datetime2` و با زمان UTC ذخیره می‌شود. مقدار `NULL` یعنی بدون محدودیت. در ارتقای اولیه هیچ مهلتی به‌طور خودکار فعال نمی‌شود.

این فیلد در فرمان ویرایش تنظیمات شرکت، فرم‌های مشتری و API نوشتن وجود ندارد؛ حتی مدیر مشتری امکان تغییرش را ندارد. فقط مالک دارای دسترسی خصوصی سرور/دیتابیس از ابزار زیر استفاده می‌کند. اطلاعات اتصال از تنظیمات خصوصی موجود خوانده می‌شود و در خروجی چاپ نمی‌شود. ابزار به دیتابیس مشترک تأییدشده `AccountingDb` روی `192.168.100.92` محدود است.

دستورها از پوشه backend اجرا می‌شوند. گزینه `--days 50` تاریخ پایان را ۵۰ روز پس از اجرای دستور تنظیم می‌کند؛ به تاریخ قبلی ۵۰ روز اضافه نمی‌کند.

```powershell
# مشاهده وضعیت، بدون تغییر
 dotnet run --project docs/tools/ManageLicense -c License --no-restore -- Accounting.Api

# فعال‌کردن اعتبار ۵۰روزه از همین لحظه
 dotnet run --project docs/tools/ManageLicense -c License --no-restore -- Accounting.Api --days 50

# تعیین تاریخ و ساعت دقیق UTC (نمونه)
 dotnet run --project docs/tools/ManageLicense -c License --no-restore -- Accounting.Api --expires-utc 2027-01-01T00:00:00Z

# حذف محدودیت زمانی
 dotnet run --project docs/tools/ManageLicense -c License --no-restore -- Accounting.Api --unlimited
```

در اولین کامپایل ابزار، در صورت نیاز به بازیابی وابستگی‌ها:

```powershell
dotnet restore docs/tools/ManageLicense --source https://api.nuget.org/v3/index.json --ignore-failed-sources
```

سرور در هر درخواست کاری، از جمله ورود و تمدید نشست، تاریخ اعتبار را از دیتابیس بررسی می‌کند. زمان دقیق پایان نیز منقضی محسوب می‌شود. پاسخ پایان اعتبار HTTP 403 و کد `license_expired` دارد. کلاینت به صفحه پایان اعتبار هدایت می‌شود. حساب‌ها، فاکتورها و داده‌ها حذف نمی‌شوند. تمدید بلافاصله روی درخواست بعدی مؤثر است و نیازی به ورود مجدد یا راه‌اندازی دوباره سرور ندارد.

`GET /api/license` فقط وضعیت اعتبار را برمی‌گرداند و بعد از انقضا هم برای بررسی تمدید قابل دسترسی است. فرانت هر دقیقه وضعیت را بررسی می‌کند و تعداد روزهای باقی‌مانده و هشدار ۷ روز آخر را نشان می‌دهد. صحت اجرای محدودیت به ساعت سرور وابسته است، نه ساعت مرورگر. health check برای بررسی سلامت سرویس باز می‌ماند.

پس از تغییر کد، نسخه تازه بک‌اند باید اجرا شود تا کنترل اعتبار فعال شود. دسترسی خصوصی سرور و SQL را در اختیار مشتری قرار ندهید؛ دارنده دسترسی کامل به دیتابیس می‌تواند تاریخ را مستقیماً تغییر دهد. برای محیطی که سرور در اختیار مشتری است، مجوز امضاشده لازم است.

migration این قابلیت: `20261018102009_SoftwareLicenseExpiry`. اسکریپت ارتقا در `docs/catering-upgrade.sql` به‌روز شده است. اجرای `--migrate` در ابزار، migrationهای معوق را اعمال می‌کند؛ از این گزینه فقط با مجوز مالک دیتابیس استفاده شود.
